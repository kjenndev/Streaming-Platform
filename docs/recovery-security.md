## Protected-channel guesses (SEC-F1)

`lib/password-budget.js` reserves an attempt atomically in Redis before comparing a protected channel password. A fixed 60-second window permits 20 reservations per transport-peer IP/subnet and stream ID. HTTP live/archive capability exchange and Socket.IO joins share the same budget. Reconnecting, switching endpoint or supplying forwarded-IP headers does not reset it. Successful password comparisons remain charged; denials do not slide the window. Trusted input is the actual socket peer, not a request header or client-supplied identity. IPv4-mapped addresses normalize to IPv4; IPv6 uses express-rate-limit's subnet grouping.

Public channels, current assigned/admin principals and valid archive renewals do not consume this password budget. Login limiting is separate and remains process-local. Redis errors/timeouts, invalid peer addresses and exhausted global state capacity fail closed for password exchange with 503; exhausted individual debt returns 429. Responses expose retry information. Already-authorized/public access bypasses this new budget (the inherited HTTP request limiter still applies).

Redis state has a fixed cardinality ceiling of 10,000 client/channel entries, bounded expiry cleanup and key TTLs. The ceiling intentionally rejects new password exchanges rather than evicting debt. This is not distributed-bot protection: a distributed attacker can saturate that global ceiling; clients sharing a NAT/proxy peer share debt. Redis eviction/restart loses the budget, so deployment must assess persistence/eviction and reverse-proxy topology. No trusted-proxy configuration is changed here.

## Managed recording lifecycle

Before creating media bytes, a durable, atomically installed versioned intent records a random UUID, immutable stream/channel association, start time and Linux host/boot/PID/start-tick owner. The source is created exclusively beneath `managed-recordings/<UUID>/source.flv`. Startup schedules recovery immediately **after media readiness**, then serial bounded sweeps continue every 30 seconds. Slow conversion must not consume the supervisor's 15-second startup deadline. Each sweep enumerates at most 128 entries and attempts at most four dead-owner intents; the retained iterator prevents early corrupt/active entries starving later ones.

Only explicit managed intents are eligible. Unknown host ownership, current live processes, unknown/legacy files, invalid manifests, absent/changed stream associations, symlinks, hard links and unsafe directories are not guessed into the catalog. Private owner-controlled real directories and non-symlink regular files are required. Linux `/proc`, machine identity and installed `/usr/bin/ffmpeg` are required; this is not a portable Windows/shared-host recovery mechanism. Use a non-dot absolute recordings root for the existing download behavior.

A transaction-scoped advisory lock serializes finalization by UUID. Media validation decodes a video frame through a held source descriptor with bounded FFmpeg runtime/output; remuxing writes an exclusive private staging output. Publication uses a directory rename and fsync; the existing Recording primary key is the durable catalog identity. The source is checked for change before catalog creation. Replay can reuse already-published validated output or an already-committed catalog identity without overwrite/duplicate. After commit, a complete intent marker avoids routine replay. It is not the deletion authority: an independent, monotonic `<UUID>.deleted` tombstone is written and file/directory-fsynced by the authenticated administrator DELETE before its SQL deletion. Deletion and recovery use the same transaction-scoped advisory lock. Recovery checks for the deletion tombstone under that lock before touching media or catalog state; a late complete-marker write cannot overwrite it.

Sources and complete intents are intentionally retained; this increases disk usage and needs an explicit reviewed retention policy. Corrupt or undecodable sources are retained and retried, not deleted. Recovery is not full-file forensic validation or salvage of arbitrary legacy recordings. Only one decoded frame is required; damaged tails may be truncated by remuxing. Filesystem guarantees assume no malicious process with the same OS identity, and Linux durable-write behavior. The commit-before-complete-marker crash window is covered by the separate deletion tombstone, including a late completion write and a fresh process replay. DELETE revalidates the current principal and catalog/intent association before persisting the tombstone. Busy finalization returns 503 for retry, never a false successful deletion. Marker write, rename or fsync failures fail closed before catalog/output removal. A SQL rollback after marker persistence can leave an extra tombstone and the original catalog row/output: the failed request has not acknowledged deletion, and an authorized retry can finish it. Repeated deletion of an absent row retains the existing 403 API behavior, with idempotent effects. Sources are retained, not indiscriminately erased. Preserve deletion tombstones alongside recordings in backup/restore and any future retention policy; removing them separately can remove the anti-replay guarantee. No schema migration is needed. Shared host/multiple independent media ownership is not certified.
