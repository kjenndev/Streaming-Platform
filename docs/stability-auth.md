# Session and login-limit stability candidate

Status: implemented and regression-tested on `feature/streaming-stability`, based on merged main `463b88c05e808bcf37b884ce944624b33133559c`. **Not independently approved, committed, pushed, or deployed.** This is the first stability slice, not completion of recovery or security verification.

## Root causes and contract

- Account middleware previously collapsed expired/invalid JWTs, deleted/empty-role accounts and database failures into 403. A locally retained token kept the protected React route mounted and dashboard failures appeared as a generic streams error. HTTP now uses 401 for absent/invalid/expired/revoked identity, 403 for an authenticated principal lacking permission, and 503 for the initial principal-store failure (other server failures remain 5xx). Current-principal checks and transactional authorization remain authoritative.
- Socket.IO previously checked JWT expiration only at connection time, and reported a generic handshake error. Handshakes now carry a structured 401/503 distinction; existing account sockets check expiration on privileged actions, broadcasts and the independent sweep. Invalid account sessions emit `session_invalid` before disconnecting. Anonymous public connections are not expired by the account policy; channel/capability revocation remains separate and fail-closed.
- A small central Axios response guard is limited to account API paths and their exact bearer identity. A relevant 401 clears token, username, roles and legacy role, then the protected route redirects with a local return path and explicit reason. Permission 403, public capability failures, transport errors and 5xx do not log out the user. Late successful responses from an older identity are cancelled; late old-identity 401s cannot clear a fresh login. Identity changes remount the protected subtree; unmount performs existing request/timer/socket cleanup.
- Public player authentication failure clears stale account identity and prepares its socket for anonymous explicit retry; it does not redirect the public route. Protected playback still requires its own valid authorization. Archive capability renewal is unchanged.
- Successful login responses previously consumed the ten-attempt, fifteen-minute IP allowance. `skipSuccessfulRequests` releases successful responses, while failures and in-flight attempts stay charged. Rejected 429 requests also remain charged. The default untrusted-proxy policy and threshold are unchanged. Retry-After is exposed through CORS; the login UI prevents overlapping submissions, displays a cooldown and re-enables retry afterward.

## Unsaved edits and limits

Identity cleanup does not clear unrelated browser storage. One stream-editor draft interrupted by an HTTP 401 is retained **only in tab memory**, scoped to the prior username and editor route, and restored after matching-account sign-in with a review notice. It is never automatically resubmitted or stored on disk/localStorage. Refreshing the tab loses it. This is not a general draft system: other forms, socket-first expiry during a save, or arbitrary navigation do not guarantee draft recovery. An expired-session message warns that unsaved changes have not been submitted.

This slice does not introduce refresh tokens, a global session-version/revocation store, password-change invalidation for account JWTs, or automatic playback/network recovery. Existing current-account and playback-policy checks are preserved. The limiter remains process-local and resets with the API process; multi-instance enforcement is a separate deployment design.

## Validation

Observed RED regressions: expired dashboard returned 403 instead of 401; repeated successful logins produced 429; frontend stayed on a phantom-authenticated dashboard; socket expiration had no structured notification; 429 had no retry UI; failed save lost its editor draft; explicit sign-out incorrectly used an expiry reason during implementation.

Final checks: **88 backend Jest tests, 56 frontend Vitest tests, 55 performance-harness unit tests, 38 native media safety tests** passed. TypeScript, isolated Vite build, frontend lint and whitespace checks passed. The Vite large-chunk advisory remains; no dependency changes or new packages were required and this slice did not rerun audits.

Backend execution used the dedicated `_test` PostgreSQL database, Redis DB1, unique temporary recording roots and isolated API/media/RTMP ports 13001/18001/11936. Existing synthetic black-media lifecycle/protocol regressions ran as part of the backend suite; no load/stress run, real upload or external provider was used. Browser QA used a synthetic account and an isolated build on 15175. Actual Chromium verified invalid-session redirect, complete identity cleanup, return-path fresh login and real 429/CORS cooldown; synthetic 403/503 browser responses retained authentication. No browser page errors were observed. QA workers were stopped and the owned account was removed.

Evidence is outside Git in the Windows Hermes cache: `streaming-stability-auth-final.json`, `streaming-stability-tests-final.log`, `streaming-stability-media-final.log`, `streaming-stability-lint-final.log`, `streaming-stability-build-final.log`, and `streaming-stability-browser/results.json` plus screenshots.
