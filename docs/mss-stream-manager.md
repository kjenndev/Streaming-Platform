# MSS Stream Manager delegated trust

This optional integration is fail-closed and isolated from normal Platform accounts, watch admission, chat, stream assignments, and keys. Enabling it requires every `MSS_DELEGATION_*` setting, an exact existing channel-to-MSS-artist map, an Ed25519 public key dedicated to MSS, and a separate authenticated introspection token. See the paired MSS `docs/stream-manager-integration.md` for activation order. Do not place grants or stream keys in URLs, logs, storage, or public DTOs.

The `/mss-manager` view accepts its short-lived grant only through an exact-origin, exact-source, one-use frame nonce handshake. It renders the shared `PlayerSession` in delegated mode, autojoins chat with structured server-derived verified artist metadata, and starts muted preview automatically after an MSS audio-exclusivity acknowledgement, unless library audio is selected. The delegated FLV path is `/mss-live/<channel>.flv`; its bounded playback capability is carried only in `X-MSS-Playback`, never a URL. The media worker checks capability expiry and performs bounded current MSS introspection on every two-second authorization sweep. An MSS outage therefore closes delegated playback without changing ordinary `/live` admission.

Before each grant expires, the parent sends a nonce- and generation-bound refresh. The existing socket revalidates it and replaces its delegated identity and media capability without remounting the frame, playback, or chat; only the current socket acknowledgement completes refresh. The replacement grant is copied into Socket.IO reconnect authentication only after that acknowledgement succeeds, so reconnects use the current accepted authority while a denied, timed-out, superseded, or late acknowledgement cannot advance it. Refresh acknowledgement has an eight-second child deadline and a ten-second parent deadline, both before the old grant's scheduled expiry margin. Timeout, denial, disconnect, expiry, or revocation terminates the child and causes the parent to remove the iframe until an explicit retry. Authorization loss synchronously clears playback, membership, chat, capability, identity, and OBS credentials. Selecting MSS audio sends a nonce-bound stop message to the manager player, and each Play request ID (the internal `mss-manager-watch-*` protocol is unchanged) is accepted at most once.

The initial HTTP exchange returns only non-secret channel context. OBS credentials are returned by the successful delegated `join_channel` acknowledgement, after current grant revalidation. `MSS_DELEGATION_INGEST_URL` must be an explicit `rtmp://` or `rtmps://` `/live` URL without credentials, query, or fragment; missing or malformed setup disables delegation. The integration cannot create/reassign channels or rotate keys. This source configuration ships disabled and contains no live keys or mappings.

The manager automatically follows live/offline status with muted preview. Library audio selection cancels pending preview acknowledgements and stops video without disconnecting chat; the video region retains its dimensions. Chat is alongside video when the embedded manager is at least600px wide, and stacks below at narrower widths. Ordinary watch and embed layouts remain unchanged.

The admitted OBS stream-key value is the complete publish name `encodeURIComponent(channelName)?key=encodeURIComponent(existingSecret)`, ready to paste into OBS alongside the separate `/live` server URL. Channel validation and existing keys are unchanged; reserved secret characters are query-encoded exactly once. MSS masks and copies this complete value without reconstructing it. This publishing string is intentionally entered into OBS; it must not be placed in browser URLs or storage.

## Automatic manager preview

The manager preview starts muted after delegated membership and the nonce-bound parent audio acknowledgement. It shows an offline placeholder when publishing stops and reconnects automatically after socket readmission. The manager has Unmute/Mute, not separate Play/Pause; these controls never start or stop OBS or publishing. Ordinary Platform watch/embed controls are unchanged.

An existing MSS library audio selection takes priority over automatic preview. Automatic requests do not close that audio; Return to preview is the explicit switch, which removes the audio iframe before acknowledging playback. A later audio selection stops preview and invalidates pending acknowledgements; live status and reconnect events cannot steal it back. Reconnected/offline-to-live preview starts muted again. Revoked authority is terminal until explicit retry; grants, nonce/source/origin checks and replay cleanup remain in force. Preview/chat dimensions retain the previous layout, including the mobile header allocation.
